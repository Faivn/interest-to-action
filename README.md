# interest-to-action
An AI-assisted product that helps people turn accumulated interests into intentional, actionable next steps.

## Development

A mobile-first web app built with Vite, React and TypeScript, styled with the Daybreak design system in [`DESIGN.md`](DESIGN.md).

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # unit and interaction tests (Vitest + Testing Library)
npm run build      # type-check and production build
```

### Live AI suggestions (Groq)

1. Create a key at [console.groq.com/keys](https://console.groq.com/keys).
2. `cp .env.example .env.local` and set `GROQ_API_KEY` in `.env.local` (git-ignored). Optionally set `GROQ_MODEL`.
3. Restart `npm run dev`. The Suggestions screen's note changes from "demo planner" to "generated by AI".
4. Optional: `npm run eval:planner` runs the five checks from `docs/ai-approach.md` §9 against the live model (a few real API calls).

On Vercel, add `GROQ_API_KEY` (and optionally `GROQ_MODEL`) under Project → Settings → Environment Variables; `api/plan.ts` is deployed automatically as a function.

Without a key, the app uses the demo planner. If Groq fails (outage, rate limit, timeout or an invalid answer), the Suggestions screen shows its error state with Try again; it does not silently switch planners.

Development-only URL options: `?planner=demo` forces the demo planner; `?latency=1500` slows loading saved plans; `?planner=fail` or `?planner=invalid` exercises the suggestion error states.

### How it fits together

- **Planning flow** (`src/features/planner/`) — the primary entry point: capture an interest → optional context → one clarification question if needed → two or three If–Then suggestions → save, edit, or dismiss → confirmation.
- **Planner** — `Planner` (`types.ts`) is the boundary for suggestions. When a Groq key is configured, `httpPlanner.ts` calls the server endpoint `/api/plan`; otherwise the clearly labelled, rule-based **demo planner** (`mockPlanner.ts`) is used. Every response is validated (`validatePlannerResult.ts`) on the server and again in the browser before it can reach the UI.
- **AI endpoint** (`server/`, `api/plan.ts`) — `planHandler.ts` validates input, calls Groq (`openai/gpt-oss-120b` by default) with a strict JSON schema and the prompt in `prompt.ts`, validates the answer, and returns only generic error codes. The same handler runs in the Vite dev server and as a Vercel Function. The key is read on the server only.
- **My Plans** (`src/features/plans/`) — saved plans in local storage: list, detail, progress (Not started · In progress · Completed), edit, and delete with Undo.
- **Design system** — tokens in `src/styles/tokens.css`; reusable primitives in `src/components/` (Button, TextField, ChipGroup, SegmentedControl, Sheet, Toast, Screen/TopBar, StepIndicator, ProvenanceTag, NumberStepper, EmptyState, Skeleton, SparkMark).
